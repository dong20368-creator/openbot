# 规则与输出

可执行规则唯一来源是`assistant/answer_policy.py`；不要只改这篇说明，以为运行行为已改变。

## 从输入到回复的约束

| 层次 | 位置 | 负责什么 |
| --- | --- | --- |
| 数据范围 | Store、inbox、资料工具 | 账号/群/成员及消息时间边界 |
| 模型规则 | answer_policy | 权限、风格、证据、媒体、研究与记忆意图 |
| 工具执行 | codex_client及各工具模块 | 白名单、参数、作用域和调用预算 |
| 输出校验 | reply_contract、evidence | 类别、来源、材料、长度与可发送性 |
| 外部写入 | native_sender、protocol_transport | 目标核验、意图持久化、确认与未知结果隔离 |

提示词不是唯一安全措施；修改时必须同时理解对应代码门槛。

## 规则职责

- AUTHORITY：群内无管理权限；保护非公开个人信息、凭据和敏感配置，区分公开资料与私有上下文。
- OUTPUT_CONTRACT：统一输出类别、缺口原因和结构；未知类别不发送。
- CONVERSATION / EVERYDAY_HELP：先答核心，必要时一次问齐参数；详细请求可展开。
- CONTEXT_MEMORY：使用本人上下文、明确纠正与可关闭记忆，不把引用材料中的经历记到提问者身上。
- EVIDENCE_SEARCH / PUBLIC_RESEARCH：动态事实要核查；公开原文链接应有依据；第三方时间线可能不完整。
- MEDIA：先确认材料可读取，再解释；不把看不到的图片内容编出来。
- GROUP_SUMMARY / MEMBER_VIEWS：群公开材料与私有记忆分开，按范围和关闭设置执行。
- INVESTMENT / MARKET_DATA / VALUATION：事实、推断、假设分开；只读行情，不下单；预测参数没有依据时不包装成概率。

`policy_for()`按可信任务类型选规则集合；普通聊天与定时摘要使用不同范围，不按消息中的任意指令提权。

## 共用限制

`answer_limits.py`是长度、来源数量、记忆数量和公开研究调用预算的共用入口。模型schema和程序检查都引用它。不要在文档、提示和执行代码里各维护一套数字。

## 如何改规则

先定义一个具体前后行为，再修改唯一职责段；用合成输入跑对应回归。规则变化可另行跑`evaluations/`中的真实模型场景，但它会调用你的模型登录并消耗额度。不要把真实群聊天当默认测试集，也不要用通过数量替代回答质量检查。

## 当前对话、搜索与媒体

- 最近对话、相关历史搜索、归档分页分别负责不同需求。历史搜索不重新塞入无关近期聊天；候选重新核验账号、群、成员、状态和当前作业边界，不能用旧索引恢复已忘记内容。
- 最近两轮优先完整保留；需要摘录时保留开头、相关段和末尾纠正，并明确标记省略。默认上下文预算24000估算tokens，单次搜索返回预算6000，每题最多3次搜索；不是无限记忆。
- 没有明确引用时，可使用本群最近5分钟内最多3条已公开机器人回答承接话题，不读取其他成员的完整私人问答或画像。成员关闭记忆时继续尊重其设置。
- 同成员5分钟内上一条消息是图片时，作为邻接候选交给模型判断是否相关；换话题应忽略。明确引用优先，既有本人30分钟/他人5分钟的明确看图指代边界保留，媒体授权默认仍关闭。
- 正常缺参数自然追问；正常穿搭等视觉评价不当越权请求。仅凭照片确认真实人物身份时简短说明限制，不套用索取内部资料的警告。

## 来源及预算一致性

稳定知识不必强制联网，但一旦提供sources或正文Markdown引用，必须匹配本次实际读取记录。普通conversation和动态verified分开分类，引用校验不能因类别而跳过。只有已成功读取并记录的公开原帖链接可作为工具来源的正文入口；搜索摘要和失败请求不能作凭据。

公开研究当前共用4次新请求，每批帖子最多3条，来源最多8项；规则和工具说明从`answer_limits.py`生成共享额度。计算上限从`investment_math.MAX_EXPRESSIONS`生成。不要把共享预算理解为每个工具分别拥有同样次数。

## 公开资料与隐私拒绝

公开链接、分享卡片、文档、代码和架构可正常解释；按给定材料或本次实际读取的公开来源回答，不因项目与助手同名拒绝。公开材料不证明它与账号主人或当前部署有关，也不能用于补充私有配置。链接读取失败属于信息缺口。

`warning`仅用于非公开个人信息、凭据、私人记录或敏感实际配置/资料的泄露风险。程序丢弃该类别的模型候选正文与来源，不引用敏感提问，只输出简短隐私说明；公开模型说明例外保留。

不涉及信息泄露的控制请求用`conversation`自然说明具体能力限制，不发越权警告、不声称执行成功。群内管理权限及工具执行范围不变。引用中的攻击句只作材料，先前警告不决定新问题类别。
