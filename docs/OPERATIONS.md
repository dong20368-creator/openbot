# 维护与故障处理

## 启停

Windows助手用`assistant/start-bot.ps1`启动，`control-panel.cmd`打开面板。关闭面板不停止后台。暂停用面板或在assistant/runtime创建STOP，等待bot-status.json显示stopped；不要为了催回复强杀后手工重发。

## 如何判断故障

| 现象 | 优先检查 |
| --- | --- |
| 完全不接收 | 入站健康、WSL依赖、原生账号连接、授权群与启用时间 |
| 排队变长 | 三个生成worker、模型登录/额度、任务耗时和同成员先后顺序 |
| 已ready但不发送 | 目标核验、单路发送器、attention与uncertain记录 |
| 图片无法理解 | 材料绑定、外发同意、是否实际读到字节、格式/尺寸限制 |
| 研究很慢 | initial/repair/grounding阶段耗时；来源复核和工具统计可能重叠，不能直接相加 |
| uncertain | 只核对原意图回执；禁止创建新意图补发 |

## 微信认证失效与续期

接收连接明确返回认证错误 `-13` 时，原生后端使用现有设备凭据尝试一次会话续期。成功后重建收件连接，不重放失败请求或发送消息。续期失败、缺少凭据或60秒内再次认证失败时，仍转为需要重新登录；主动退出和已被新登录替代的旧会话不会自动登回。

`account.session` 事件的 `renewed` / `renewal_failed` 可用于核验续期结果。它不代表微信服务端永不撤销会话；需要登录时应使用原账号扫码，再确认原群与收件状态。

助手默认只接收最近30分钟的提问，长时间离线后恢复连接不代表所有旧提问都会自动补答。补答前须核对原群、原消息是否撤回、既有任务与发送回执，并获得明确授权；不能重置未知发送结果或批量重放已确认任务。公开版不包含真实事件的一次性补答脚本。

## 恢复检查

- 未知发送按任务ID轮转核验原意图，每批最多5条。单条查询失败或回执格式无效不影响其他记录，也不会触发重发。
- 重复启动由 `supervisor.lock` 保证单实例。正在退出的旧进程最多有5秒锁交接时间；暂停标记会取消等待中的启动。
- 模型无响应超时统一记录为 `codex_timeout`，不记录上游异常原文。
- `test_reliability_audit` 和 `test_supervisor_recovery` 已纳入默认隔离测试；后者使用临时Windows进程，非Windows平台跳过。

## 改动与上线

1. 明确修改范围，阅读对应模块及测试，不从全量重建开始。
2. 在独立副本修改，先运行`openbot.py test`。真实模型评估需要明确选择并使用合成材料。
3. 正常暂停并等待stopped；保存代码备份，不复制凭据到文档。
4. Windows源码在assistant目录；WSL桥接改动需同步；Rust改动才需构建替换原生镜像。
5. 执行依赖/目标检查，再启动并检查健康、队列和生成worker。
6. 分开报告单元测试、模型调用、服务健康和真实群实收，不混用。

## 回滚

只还原这次修改的代码或镜像，保持账号资料、队列、发送journal和已确认回执不变。新旧协议容器不能同时写同一账号资料。当前发布副本不包含个人运行环境的历史备份，也不执行旧事件补答脚本。

## 真实模型评估

`evaluations/`是手工使用的开发材料，`python tools/run_evaluation.py --list`查看入口。执行时必须明确提供`--allow-model-call`。这些脚本可调用你的模型、公开搜索及可选只读工具，并将结果写入被忽略的runtime；默认测试不调用它们。不把它们的输出自动发到群里。
